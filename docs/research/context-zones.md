# Context zones: OS UI geometry for wallpaper mockups

Purpose: approximate sizes of the OS chrome that cromatica draws over the wallpaper preview (bars, notch, dock, clock, icon grid) and the zones the legibility check samples. Values are measured where a source or device allows it (D56); the rest are marked as estimates to replace when a measurement turns up.

Units: logical units of the reference device: pt (Apple), epx at 100% scale (Windows), dp (Android). Origin is the top-left of the screen.

Anchors: each zone has a fixed size in logical units and is pinned to an edge or centred on an axis. It is not stored as a fraction of the screen. This lets mockups adapt to any aspect ratio. On an ultrawide, the menu bar and taskbar get wider, and the Dock and Start cluster stay centred at the same size.

- `top-stretch` / `bottom-stretch`: full width, fixed height, flush to that edge.
- `top-center` / `bottom-center`: fixed w×h, centred horizontally, offset `y` from that edge.
- `top-left`, `top-right`, `bottom-left`, `bottom-right`: fixed w×h, offset from those two edges.
- Grids: cell size, column/row count, insets, and the corner the grid starts from.

Rects are written `x, y, w, h` on the reference screen. For edge-anchored zones, the offset from the anchor edge is what counts.

Confidence: **high** = read from first-party source code, config or API docs. **medium** = derived from a primary value, or a consistent simulator/runtime value reported second-hand. **low** = estimate from screenshots or common knowledge. Treat low values as starting points to tune by eye.

## macOS 26 Tahoe: MacBook Pro 14", default scaled 1512 × 982 pt

**Used in the app:** measured on a MacBook Pro 16-inch running macOS 27.0.1 at 1800 × 1169 pt, with `NSScreen.safeAreaInsets`, `auxiliaryTopLeftArea` and `auxiliaryTopRightArea`. Safe-area top 38 pt, each auxiliary area 790 × 38 pt, so the menu bar is **38 pt** tall and the notch **220 × 38 pt** (1800 − 2 × 790). Confidence: high for that device and scaling. The 14-inch values below are secondhand and kept for reference.

Apple does not publish menu bar, Dock or notch sizes. At runtime they come from `NSScreen.safeAreaInsets`, `auxiliaryTopLeftArea`/`auxiliaryTopRightArea` and `NSMenu.menuBarHeight`. The values below are runtime readings reported by developers, or estimates.

## Gaps and estimates

- **No first-party pixel specs** exist for the macOS menu bar, Dock or notch, the Windows 11 taskbar, the iOS Dynamic Island, the lock screen or the home grid, or the Pixel Launcher. All values for these are runtime readings reported by third parties, or screenshot estimates. Tune them by eye against current screenshots.
- **macOS menu bar height** is reported as 32 (safe-area inset) to 37 pt, and Tahoe reportedly changed it. Use 32 and treat it as adjustable. The notch width of 185 pt comes from a secondary source.
- **Dock width** depends on how many apps are in the Dock. Model it as `n × 52 + padding` and keep it centred.
- **Windows** centre-cluster, tray and Widgets widths are estimates. The 48 epx taskbar height is consistent across third-party sources but not stated on Microsoft Learn.
- **iOS** status bar 54, safe areas 62/34 and screen size are reliable. Everything on the lock screen and home screen is a low-confidence estimate. On iOS 26 the lock-screen clock can resize itself.
- **Pixel 9 height** is 923 dp from AOSP density and resolution, not 915. The status bar (66 dp) and the 24 dp gesture-nav inset are read from source. Clock, At a Glance, hotseat and QSB are estimates, and the Pixel Launcher default grid (4 × 5 vs 5 × 5) is unverified.
- **Not done** (measurement would be needed to raise confidence): pixel-measuring official screenshots or Apple design-resource templates, and reading `NSScreen` and simulator values on real hardware. Running a 3-line Swift snippet on the 14" MBP (`safeAreaInsets`, `auxiliaryTopLeftArea`, `NSMenu.menuBarHeight`) would settle the macOS numbers.
